01 — ABSTRACT

Agents need infrastructure, not promises.

AI agents are becoming autonomous economic actors — they research, code, trade, and hire each other. But they lack the most basic financial primitives: identity, spending limits, and trustless settlement.

AXON Protocol ships these primitives as native Soroban contracts on Stellar — all four deployed and unit-tested on testnet today:

🆔

Agent Identity

💰

🤝

Trustless Escrow

Funds locked until delivery. Mutual cancel. 0.3% fee.

🚀

AXON Pad

Token sales gated by verified agent identity — anti-rug by design.

02 — THE PROBLEM

Autonomous actors, zero accountability.

An agent that can move money with no on-chain identity is an untraceable counterparty. An agent wallet with no spending cap is an unbounded liability. A sale by an anonymous dev is a probable rug.

No identity — agents can't prove who operates them or accumulate portable reputation across platforms.

No bounded autonomy — there is no standard way to let an agent spend "up to X per day, only to these addresses, freezable at any moment."

No trustless settlement — agent-to-agent work requires trusting the counterparty or a centralized intermediary.

No accountable launches — token launches have no enforced link between the token and a verified, accountable developer identity.

These are infrastructure gaps, not product gaps — they belong at the protocol layer.

03 — THE SOLUTION

Four primitives, one layer.

AXON sits beneath any agent framework (custom agents, LangChain-style pipelines, autonomous bots) and provides:

  1. Identity — each agent registers in the AgentRegistry with an owner, an operator key, and metadata. Publicly verifiable in one contract call.
  2. Bounded financial autonomy — the owner binds a cap-guarded wallet: per-transaction caps, rolling 24-hour limits, destination whitelists, and an emergency freeze.
  3. Trustless commerce — escrow holds funds until delivery is confirmed; both sides can mutually cancel; every outcome updates on-chain reputation.
  4. Accountable launches — AXON Pad only allows sales from verified, active agents, with the full allocation escrowed in-contract before the sale opens.

We complement agent frameworks; we don't compete with them. And every primitive is Soroban-native — no bridged EVM code, no wrappers.

04 — ARCHITECTURE

Built where agents can afford to operate.

Stellar was chosen as our primary and only chain: ~$0.00001 transaction fees make agent micro-payments economically viable, finality is fast, and Soroban's resource-metered execution model maps naturally onto spending caps.

05 — AGENT REGISTRY

One agent, one verifiable identity.

The AgentRegistry maps every agent to a public record: owner (the accountable human), operator (the authorized agent key), metadata URI, an active flag, reputation score, and task count.

// Register an agent (Soroban) let agent_id = registry.register(owner, operator, metadata_uri); // Any dApp verifies in one call let agent = registry.get_agent(agent_id); // agent.active == true, agent.reputation, agent.owner …

Operator delegation: the human owner remains accountable while an autonomous key operates day-to-day. Operators can be rotated or deactivated instantly — deactivation propagates to every AXON component that checks identity.

06 — CAP-GUARDED WALLETS

Autonomy within hard limits.

The AgentWallet contract lets a human owner delegate spending power to an agent with on-chain enforced boundaries:

📊

Per-transaction cap

No single send can exceed the owner's limit.

⏱️

Rolling 24h limit

Daily spending window enforced in-contract.

✅

Destination whitelist

Operator can only send to pre-approved addresses.

🧊

Emergency freeze

Owner freezes instantly; withdrawals still work.

This answers the question every institution asks about agentic payments — "what happens when the agent goes rogue?" — with a contract answer, not a policy answer.

07 — TRUSTLESS ESCROW

Settlement without trust.

// Agent-to-agent commerce open(provider, token, amount) // client locks funds release(escrow_id) // delivery confirmed → paid mutual_cancel(escrow_id) // both agree → refund // protocol fee: 0.3% on release

Escrow removes counterparty risk on funds; reputation (below) addresses risk on quality — the same layered model that powers modern marketplaces, executed entirely on-chain.

08 — AXON PAD

Fair launches with verified identity.

AXON Pad is the revenue engine of the protocol — and the first launchpad where the anti-rug guarantee is enforced at the contract level:

1. Identity gate. create_sale() calls the AgentRegistry: the launcher must be a registered, active agent. Unregistered dev → the transaction reverts.

2. Full allocation escrowed. The entire token supply for the sale is transferred into the TokenSale contract at creation. The dev cannot pull it back.

3. Buyer protection. Hard cap, minimum buy, and time bounds enforced on-chain; buyers claim trustlessly after finalize.

Protocol fee: 1.5% of every sale (basis-point configurable). This sustains development after the grant ends — the protocol outlives its funding.

A live demo sale (#0) is running on Stellar testnet, launched by demo Agent #1, with the identity gate exercised by a real cross-contract call.

09 — REPUTATION

Trust as verifiable history.

  • Successful escrow releases build an agent's on-chain reputation score.
  • Disputes and cancellations are visible history — persistent and portable.
  • Any dApp can read an agent's record in one call and use it as a trust signal.
  • Planned: an agent performance dashboard (community-requested) indexing tasks, escrow outcomes, and reputation changes over time.

The design principle: keep the settlement layer minimal, let trust compound. On-chain escrow plus reputation builds an accountability graph that no centralized platform can revoke.
